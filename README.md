# Нова Пошта — бот грузовых отделений

Telegram-бот для работы с грузовыми («Вантажне відділення») отделениями
Новой Почты: поиск ближайшего отделения, расчёт сроков и стоимости доставки.

Стек: Python 3.11+, [aiogram 3.x](https://docs.aiogram.dev/) (async, FSM),
`httpx`, `aiosqlite`, `pydantic-settings`, `APScheduler`. Деплой — GitHub →
Railway через Nixpacks (без Docker).

## Возможности

- **📍 Найти отделение** — по городу и адресу показывает 3 ближайших грузовых
  отделения с расстоянием, лимитами веса, расписанием и ссылкой на карту.
  Если в городе грузового отделения нет — ищет ближайшие в радиусе 50 км.
- **⏱ Просчитать сроки** — ориентировочная дата доставки между двумя городами.
- **💰 Просчитать стоимость** — расчёт цены с учётом объёмного веса плюс срок
  доставки в том же ответе.

## Как это устроено

Справочники Новой Почты (50k+ отделений) кэшируются локально в SQLite и
обновляются раз в сутки — API не дёргается на каждое сообщение. При старте,
если кэш пуст или старше 24 часов, запускается фоновая синхронизация; пока она
идёт, бот отвечает «Обновляю справочники». Ежедневное обновление — в 04:00
по Киеву (`APScheduler`).

GUID типа «грузовое отделение» **не захардкожен**: при первой синхронизации
бот вызывает `getWarehouseTypes`, находит «Вантажне відділення» и сохраняет
его `Ref` в таблицу `meta`.

## Структура

```
bot/
  main.py              # точка входа, роутеры, старт polling, планировщик
  config.py            # Settings из переменных окружения
  states.py            # FSM-состояния
  keyboards.py         # меню и инлайн-клавиатуры
  texts.py             # все тексты (русские)
  widgets.py           # переиспользуемый виджет выбора города
  utils.py             # парсеры, объёмный вес, форматирование дат
  handlers/            # common, find_warehouse, delivery_date, price
  services/            # novaposhta, cache, geocoder, geo
scripts/
  smoke_test.py        # проверка API-ключа и структуры ответа
  sync.py              # ручная синхронизация справочников
Procfile               # worker: python -m bot.main
railway.json           # numReplicas: 1, Nixpacks
```

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # и заполнить BOT_TOKEN, NP_API_KEY
```

Проверить, что API-ключ рабочий и структура ответа ожидаемая:

```bash
python -m scripts.smoke_test
```

Наполнить локальный кэш справочников (первый раз — несколько минут):

```bash
python -m scripts.sync
```

Запустить бота:

```bash
python -m bot.main
```

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `NP_API_KEY` | да | API-ключ Новой Почты |
| `DB_PATH` | нет | Путь к SQLite (на Railway — `/data/np.db`) |
| `GEOCODER_USER_AGENT` | нет | User-Agent для Nominatim (с контактом!) |
| `GEOCODER_PROVIDER` | нет | `nominatim` (по умолчанию) |
| `LOG_LEVEL` | нет | `INFO` по умолчанию |

## Получение токенов

**Telegram-бот (@BotFather):**
1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`.
2. Задайте имя и username бота.
3. Скопируйте выданный токен в `BOT_TOKEN`.

**API-ключ Новой Почты:**
1. Войдите в [личный кабинет НП](https://new.novaposhta.ua/).
2. Настройки → Безопасность → Ключи API.
3. Создайте ключ и скопируйте его в `NP_API_KEY`.

## Деплой на Railway

Бот разворачивается как **worker** (long polling, без webhook — публичный URL
и `$PORT` не нужны). Nixpacks сам соберёт проект по `requirements.txt`.

1. **Подключите репозиторий.** Railway → New Project → Deploy from GitHub repo,
   выберите этот репозиторий.

2. **Добавьте Volume (обязательно!).** Файловая система Railway эфемерная —
   без тома SQLite-файл сотрётся при каждом редеплое, и бот будет заново
   тянуть 50k+ отделений при каждом запуске.
   - Service → Settings → Volumes → **New Volume**, mount path: `/data`.
   - В переменных окружения выставьте `DB_PATH=/data/np.db`.

3. **Только одна реплика.** Long polling с двух инстансов даёт Telegram
   `409 Conflict`. `numReplicas: 1` уже зафиксировано в `railway.json`;
   не увеличивайте число реплик в настройках сервиса.

4. **Задайте переменные окружения** (Service → Variables):
   `BOT_TOKEN`, `NP_API_KEY`, `DB_PATH=/data/np.db`, `GEOCODER_USER_AGENT`,
   при желании `LOG_LEVEL`.

5. **Первый запуск.** При первом старте бот начнёт фоновую синхронизацию
   справочников. Пока она идёт (пара минут), на запросы он отвечает
   «Обновляю справочники, попробуйте через пару минут». Дождитесь в логах
   строки «Синхронизация завершена» — после этого сценарии работают.

Редеплой Railway шлёт `SIGTERM`; бот обрабатывает его и корректно закрывает
`httpx`-сессии и планировщик.

## Лицензионные заметки

Геокодинг — [Nominatim](https://operations.osmfoundation.org/policies/nominatim/)
(OpenStreetMap): не больше 1 запроса в секунду и обязательный содержательный
`User-Agent`. Бот соблюдает рейт-лимит и кэширует результаты геокодинга.
Для больших нагрузок замените провайдер на Google Geocoding
(`services/geocoder.py` — интерфейс уже готов под подмену).
