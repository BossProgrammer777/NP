# Промпт для Claude Code: Telegram-бот «Нова Пошта — грузовые отделения»

## Задача

Собери Telegram-бота на Python для работы с API Новой Почты. Деплой — GitHub → Railway.
Строй по этапам (см. раздел «Порядок работы» в конце), после каждого этапа останавливайся и показывай, что получилось.

## Стек

- Python 3.11+
- `aiogram` 3.x (async, FSM через `StatesGroup`)
- `httpx` (async HTTP-клиент)
- `aiosqlite` — локальный кэш справочников НП
- `pydantic-settings` — конфиг из переменных окружения
- Без Docker: Railway соберёт через Nixpacks по `requirements.txt`

## Клиент API Новой Почты (`services/novaposhta.py`)

Один эндпоинт: `POST https://api.novaposhta.ua/v2.0/json/`

Тело любого запроса:
```json
{
  "apiKey": "...",
  "modelName": "Address",
  "calledMethod": "getWarehouses",
  "methodProperties": { }
}
```

Требования к клиенту:
- Один общий метод `call(model, method, props) -> list[dict]`
- Ответ всегда содержит `success`, `data`, `errors`, `warnings`. При `success: false` — подними своё исключение `NovaPoshtaError` с текстом из `errors`, чтобы хендлер показал пользователю понятное сообщение, а не трейсбек
- Таймаут 15 сек, 2 ретрая с экспоненциальной задержкой на сетевых ошибках и 5xx
- `asyncio.Semaphore` на 5 одновременных запросов — не долби API
- Логируй `modelName/calledMethod` и время ответа

Методы, которые нужны:

| Что | Модель | Метод | Ключевые параметры |
|---|---|---|---|
| Справочник населённых пунктов | `Address` | `getSettlements` | `Page`, `Limit`, `Warehouse: 1` |
| Быстрый поиск города | `Address` | `searchSettlements` | `CityName`, `Limit` |
| Типы отделений | `Address` | `getWarehouseTypes` | — |
| Отделения | `Address` | `getWarehouses` | `CityRef`, `TypeOfWarehouseRef`, `Page`, `Limit` |
| Стоимость | `InternetDocument` | `getDocumentPrice` | `CitySender`, `CityRecipient`, `ServiceType`, `Weight`, `Cost`, `CargoType`, `SeatsAmount`, `OptionsSeat` |
| Срок доставки | `InternetDocument` | `getDocumentDeliveryDate` | `DateTime` (`dd.mm.yyyy`), `ServiceType`, `CitySender`, `CityRecipient` |

**Важно: не хардкодь GUID типа отделения.** При первой синхронизации вызови `getWarehouseTypes`, найди в ответе запись с грузовым отделением («Вантажне відділення») и сохрани её `Ref` в таблицу `meta`. Если не нашлась — упади с внятной ошибкой в лог, а не молча.

## Кэш справочников (`services/cache.py`)

НП требует хранить копию справочников у себя и обновлять раз в сутки. Отделений больше 50 тысяч — дёргать API на каждое сообщение пользователя нельзя.

Таблицы:

```sql
settlements (
  ref TEXT PRIMARY KEY,
  description TEXT,
  area TEXT,               -- область
  region TEXT,             -- район
  settlement_type TEXT,    -- село/смт/місто
  latitude REAL,
  longitude REAL
)

warehouses (
  ref TEXT PRIMARY KEY,
  number TEXT,
  description TEXT,
  short_address TEXT,
  city_ref TEXT,
  type_ref TEXT,
  latitude REAL,
  longitude REAL,
  total_max_weight REAL,   -- TotalMaxWeightAllowed
  place_max_weight REAL,   -- PlaceMaxWeightAllowed
  schedule TEXT,           -- JSON как есть
  status TEXT              -- WarehouseStatus
)

meta (key TEXT PRIMARY KEY, value TEXT)   -- last_sync_at, cargo_type_ref
```

Индексы на `warehouses(city_ref, type_ref)` и `settlements(description)`.

Синхронизация:
- Постранично, `Page` начиная с 1, `Limit` подбери эмпирически (начни с 500 для отделений, 150 для населённых пунктов; если API ругается — уменьшай)
- Пиши батчами в транзакции, не по одной строке
- **Отфильтруй мусор:** записи с `latitude`/`longitude` равными 0, `null` или пустой строке выбрасывай. Иначе «ближайшим» отделением окажется точка в Гвинейском заливе
- Отбрасывай отделения с `WarehouseStatus`, отличным от рабочего
- При старте: если `last_sync_at` старше 24 часов или таблицы пустые — синхронизируй. Плюс `APScheduler` с ежедневным запуском в 4:00
- Первая синхронизация долгая — на время неё бот должен отвечать «Обновляю справочники, попробуйте через пару минут», а не молчать

## Сценарий 1 — 📍 Найти отделение

FSM: `waiting_city` → (при неоднозначности) `choosing_city` → `waiting_street` → результат

1. Пользователь вводит город. Ищи в кэше по `LIKE` + нормализация (регистр, `і/и`, `ї/й`, апострофы)
2. **Если совпадений несколько — обязательно покажи инлайн-кнопки с уточнением** в формате `Олександрівка, Кіровоградська обл., Кропивницький р-н`. Тёзок в Украине очень много, без этого шага бот будет врать
3. Пользователь вводит улицу с номером дома. Геокодишь строку `Україна, {область}, {город}, {улица}` через Nominatim
4. Из кэша берёшь отделения с `city_ref = выбранный` и `type_ref = cargo_type_ref`
5. Считаешь haversine до каждого, берёшь 3 ближайших
6. **Фолбэк:** если в городе нет грузовых отделений — ищи в радиусе 50 км по координатам населённых пунктов и явно предупреди: «В {город} грузового отделения нет, ближайшие — в {другой город}»
7. Если геокодер не нашёл улицу — не падай: выдай все грузовые отделения города списком с пометкой «не смог определить адрес, вот все отделения»

Формат ответа на отделение:
```
🏢 Грузовое отделение №15
📍 ул. Промышленная, 42
📏 ~2.3 км от вас
⚖️ до 1000 кг на место, 15000 кг всего
🕐 Пн-Пт 09:00-19:00, Сб 09:00-16:00
🗺 https://www.google.com/maps/search/?api=1&query={lat},{lon}
```

## Сценарий 2 — ⏱ Просчитать сроки

FSM: `waiting_sender_city` → `waiting_recipient_city` → `waiting_service_type` → результат

- Города выбираются тем же переиспользуемым виджетом, что и в сценарии 1 (вынеси в отдельную функцию, не копипасть)
- `ServiceType` — четыре инлайн-кнопки: `WarehouseWarehouse` (Склад-Склад), `WarehouseDoors` (Склад-Двери), `DoorsWarehouse` (Двери-Склад), `DoorsDoors` (Двери-Двери)
- `DateTime` = сегодня в формате `dd.mm.yyyy`
- Ответ приходит вложенным объектом с датой — распарси и покажи по-человечески: дату + сколько это дней от сегодня
- Подпиши, что дата ориентировочная

## Сценарий 3 — 💰 Просчитать стоимость

FSM: `waiting_sender_city` → `waiting_recipient_city` → `waiting_service_type` → `waiting_weight` → `waiting_dimensions` → `waiting_declared_cost` → `waiting_seats` → результат

- `CargoType`: `Cargo`
- Вес — в кг, дробные через точку и запятую оба принимай
- Габариты — строкой `ДxШxВ` в сантиметрах, с кнопкой «Пропустить»
- **Объёмный вес считается обязательно.** Для груза НП тарифицирует по большему из фактического и объёмного веса. Передавай массив `OptionsSeat` с габаритами каждого места — без него расчёт будет занижен, и клиент увидит одну цену, а на кассе другую. Если пользователь габариты пропустил — покажи цену с явной пометкой «без учёта объёмного веса, финальная сумма может быть выше»
- `Cost` — объявленная стоимость в гривнах, влияет на страховой сбор
- `SeatsAmount` — количество мест
- В том же ответе сразу дёрни `getDocumentDeliveryDate` и покажи цену и срок вместе — это удобнее, чем гонять пользователя по двум сценариям

Формат ответа:
```
💰 Стоимость: 480 грн
📅 Ориентировочная доставка: 25.07.2026 (через 2 дня)
📦 Расчётный вес: 45 кг (объёмный)
⚠️ Предварительный расчёт, финальная стоимость определяется при приёме груза
```

## Геокодер (`services/geocoder.py`)

Nominatim (OpenStreetMap), бесплатно, но с условиями:
- Обязательный `User-Agent` с названием проекта и контактом — иначе забанят по IP
- Не больше 1 запроса в секунду: рейт-лимит через `asyncio.Lock` + `sleep`
- Кэшируй результаты геокодинга в SQLite по нормализованной строке адреса — одни и те же адреса будут повторяться
- Оберни в интерфейс, чтобы позже можно было подменить на Google Geocoding одной строкой в конфиге

## Общие требования к UX

- Главное меню — `ReplyKeyboardMarkup` с тремя кнопками, всегда доступно
- `/cancel` и кнопка «Отмена» на каждом шаге — сбрасывают FSM в меню
- Валидация чисел: на «пять кг» отвечай «Введите вес числом, например 12.5», а не молчи и не падай
- Все тексты бота — на русском, вынеси их в отдельный модуль `texts.py`, чтобы потом легко перевести на украинский
- `Description` из НП приходит на украинском; если в ответе есть `DescriptionRu` — используй его, иначе украинский вариант
- Ошибки API показывай пользователю коротким понятным сообщением, полный трейс — только в лог

## Деплой на Railway

Это важная часть, не пропусти.

- **Файловая система на Railway эфемерная.** SQLite-файл сотрётся при каждом редеплое, и бот будет заново тянуть 50к отделений. Нужен Railway Volume: смонтировать на `/data`, а `DB_PATH` в переменных окружения выставить в `/data/np.db`. Опиши это в README пошагово
- **Только одна реплика.** Long polling с двух инстансов даёт Telegram 409 Conflict. Зафиксируй `numReplicas: 1` в `railway.json` и напиши об этом в README
- Long polling, не webhook — не нужен публичный URL и не нужно биндить `$PORT`. Сервис разворачивается как worker
- `Procfile`:
  ```
  worker: python -m bot.main
  ```
- `.env.example` со всеми переменными и комментариями: `BOT_TOKEN`, `NP_API_KEY`, `DB_PATH`, `GEOCODER_USER_AGENT`, `LOG_LEVEL`
- `.gitignore`: `.env`, `*.db`, `__pycache__/`, `.venv/`
- Graceful shutdown по `SIGTERM` — Railway шлёт его при редеплое, иначе висящие сессии `httpx` дадут warning'и
- README: создание бота у @BotFather, получение API-ключа НП (личный кабинет → Настройки → Безопасность), подключение репозитория к Railway, добавление Volume, выставление переменных, первый запуск
